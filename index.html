STORY

自傳

關於我

我是吳明翰，資訊管理背景出身，從伺服器維修做到軟韌體測試，現在主要在做測試資料的自動化。我的習慣是遇到問題先弄清楚根因再動手，數字對不上時會回頭查判定邏輯，而不是把表面結果改對就算了。個性上我算開朗好溝通，在團隊裡常扮演橋樑的角色。工作之外我喜歡閱讀心理學書籍與運動，前者讓我更懂得怎麼跟不同立場的人對話，後者讓我在高壓期間還能維持穩定。

大學專題：第一次完整交付一個東西

大學時我參與一個與自身家庭行業相關的專題，主題是麻油產業的品牌網站規劃與建置。我負責資料與數據的收集整合，並直接與業主溝通需求，把大量雜訊過濾掉，整理成組員能看懂的簡報再進行分工。這是我第一次完整走過「需求訪談、資料整理、網頁設計、成果報告」的流程，也讓我發現自己真正的興趣在於把混亂的資訊整理成可用的東西。

碩士：學會用資料說話

為了補足資料分析能力，我進入高科大資管所。碩士論文以工作要求－資源模式探討遠距工作者的工作績效及其影響因素，從問卷設計、樣本蒐集、信效度檢驗到以 SPSS 與 SmartPLS 驗證研究模型，完整跑過一次量化研究的流程。這段訓練讓我習慣先問「這個數字怎麼算出來的、樣本有沒有被污染」，而不是直接相信報表。課餘我自學 Python 與 scikit-learn，把所學做成股票查詢與走勢預測的個人專案，這是我開始大量寫程式的起點。

RMA 維修：把手弄髒的兩年半

畢業後我進入緯穎 RMA 部門，負責伺服器板卡的 IC 級維修：操作 BGA 機台拆換不良 IC、以 X-ray 檢查錫球與氣泡、用顯微鏡微調 CPU 針腳，並以 Cadence Allegro 查看點位判斷短路風險。我不只把件修好，也會回頭找為什麼修不好：機台參數怎麼調才能讓 Sample 穩定、載具與鋼片規格要提供哪些數據、哪些手法應該寫進 SOP。這兩年半我把維修 WIP 維持在 5% 以下、良率 97%。這段經歷讓我對伺服器硬體有實際手感，後來做測試與 Debug 時，判斷問題落在哪一層會比別人快。

轉任軟韌體測試工程師：從硬體走到系統

碩士畢業後我回到緯穎，轉任軟韌體測試工程師，負責 Meta 與 AWS 伺服器產品的測試驗證與異常排除，兩個平台合計 14 個專案，每天大約處理 5 到 10 件異常。Meta 平台我做 BMC 驅動的 bring-up 與 debug；AWS 平台則多半從 OS 端檢查 PCIe、GPU 與 Driver，搭配壓力與效能測試，判斷問題落在網路、PCIe、Driver 還是 FW。測試環境的網路也由我負責，使用 Cisco、Edge-Core、Wedge100/400 設定路由器與交換器。

測試工程自動化平台：把重複的工作變成系統

我發現部門花了大量時間在人工查資料庫、整理報表，同一份數字每天有人重算一次，因此從零建置了測試工程自動化平台。用 Python 搭配 MS SQL 與 Linux 排程，自動解析站台原始 log、每日新增逾 100 筆測試場次資料，十餘支程式接力執行並具備階段失敗偵測，產出五個報表頁並以 Teams 推播日報。導入前每天要專人花約一小時整理報表，現在只需約五分鐘確認，每個月省下約 20 個工時。

這個專案讓我學最多的是資料正確性與變更安全。統計數字怪怪的時候，追下去才發現是判定邏輯的問題，所以我重新設計了場次與 SN 生命週期規則，誤判才真正消失。我也導入服務健康監控，多數異常在 3 到 5 分鐘內就會知道。動正式環境時，我一定先乾跑模擬、驗證比對次數，數量不符就整批中止，通過後自動備份並經語法檢查才落地。最後建置的地端智慧問答系統已完成、近期開放部門使用；先前實作的地端 LLM + RAG 版本，則依公司資料治理規範完整下架封存。

跨部門協調

我參與過兩次部門遷移，擔任現場核心協調角色，負責跨單位溝通、人力調度與網路環境建置，並即時處理突發狀況。這類工作技術含量不一定最高，但很吃溝通與事前規劃，也是我相對擅長的部分。

個人專案與下一步

工作之外我持續寫自己的專案：串接證交所 OpenAPI 的台股查詢平台，以及用決策樹、隨機森林做的股價走勢預測，並以 GitHub Actions 每天自動重新訓練；也把大學專題網站整體重做，並把碩士論文放上個人網站，原始碼都在 GitHub。接下來我希望專注在測試開發與自動化，結合對伺服器硬體的理解與程式能力，繼續做出真正能讓團隊省下時間的工具。
